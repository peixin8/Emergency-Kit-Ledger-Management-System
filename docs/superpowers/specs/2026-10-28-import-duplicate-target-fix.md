# Excel 导入重复目标修复（R1）

## 问题与依据

已确认的导入覆盖设计要求：文件内重复编号报错，整份文件回滚。字面字符串去重与数据库排序规则可能不同；不同大小写或其他数据库视为相等的编号可命中同一记录，导致后行覆盖前行。本次按 Planner 契约增量修复，不改变编号的数据库匹配语义。

## 修复契约

- 保留现有字面编号去重，并按数据库实际解析的目标记录 ID 增加单文件去重；新建行也登记生成的 ID。
- 内部 upsert 结果可携带 ID 和新增/更新结果。Excel 层发现重复目标后抛出文件重复异常，依靠现有外层事务回滚全部台账、版本与审计写入。
- 重复目标保持 HTTP 409、`DUPLICATE_LEDGER_CODE`，提示第二次命中的实际 Excel 行号及文件内重复原因，不改写成普通数据库编号冲突。
- 保留跨组织全局匹配、多记录歧义 `AMBIGUOUS_LEDGER_CODE`、软删除冲突及现有优先级；保留共享工作区锁、唯一约束、版本检查及事务边界。
- ID 集合只用于当前文件，不缓存到跨请求状态，不替代数据库并发保护。不采用转小写等近似比较，不修改排序规则或迁移。
- 对外接口、成功响应及前端无变化。

## 范围与验收

Backend 修改导入服务、台账服务内部结果及相关测试，Reviewer 独立复审。测试覆盖：完全相同编号；数据库判为相等的不同字面编号分别命中已有记录和本次新建记录；前行新增、覆盖、版本与审计以及夹在重复行之间的合法行全部回滚；数据库判为不同的编号正常导入。原跨组织歧义、软删除和并发检查继续通过。

执行 `backend/mvnw.cmd verify`。可在隔离 H2 中配置不同字符串比较语义验证目标 ID 去重，但不得将结果表述为 MySQL 排序规则已验证。本机无可用 MySQL 时记录该限制，真实 MySQL 需在独立临时数据库中另行验证，禁止使用用户业务库。
