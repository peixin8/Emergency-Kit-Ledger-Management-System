# 合并后的 Excel 覆盖兼容性修复

## 依据与范围

本次恢复 `main` 与 `upstream/main` 的合并，保留 V2 跨组织共享台账以及已确认的 Excel 按编号覆盖。独立审查发现 MR-01（P2）：按默认组织匹配编号会漏掉共享列表中可见的旧组织记录，重导时生成新 ID，或选错覆盖对象。本补充契约由 Planner 只读分析后确定，Frontend 无新增变更。

## 匹配与错误契约

- 去除首尾空白后的台账编号在所有组织中匹配，包含软删除记录。
- 无匹配：在默认共享组织新增，生成 ID 并记录 CREATE。
- 唯一未删除匹配：覆盖业务字段，空白清空旧值；保留原 ID、组织、创建时间和既有历史，递增版本，并在原组织下记录 UPDATE。
- 唯一已删除匹配：HTTP 409、`DUPLICATE_LEDGER_CODE`，禁止复活或重新占用。
- 多个匹配：HTTP 409、`AMBIGUOUS_LEDGER_CODE`，提示“第 N 行：台账编号对应多条历史记录，无法确定覆盖目标”。包含活跃与已删除组合，不默认挑选某一组织或活跃记录。
- 任一错误整文件回滚，包含之前新增、覆盖和审计。沿用共享工作区锁与乐观锁。
- 不新增接口或数据库迁移，成功响应与前端契约不变。

## 实现与验收

Backend 调整 `LedgerRepository` 全局编号匹配及 `LedgerService.importUpsert` 分支，复用保留原组织的更新与审计逻辑。Excel 错误保留行号、状态码和业务错误码。

隔离数据库用例覆盖：旧组织导出后重导保留身份且写 UPDATE；默认组织与旧组织、两个旧组织、活跃与已删除同编号均拒绝歧义；唯一旧组织已删除编号不可重占；前行新增或覆盖后，后行歧义或已删除时整批回滚。原有新编号、正常覆盖、空白清空、导入计数及上传边界继续验证。

Frontend 保留远程移除首页筛选的 `reset()`，同时保留本地 `formSession` 表单会话重置修复。Reviewer 独立复审，主 Agent 在前端检查与后端 `verify` 通过后标记冲突解决；本任务不自动提交或推送。
