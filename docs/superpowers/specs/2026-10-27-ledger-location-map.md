# 应急宝台账精确点位设计

## 目标与范围

首页在厦门地图上按台账逐台显示设备目标地址对应的精确点位。文字地址不能可靠地转换成精确坐标，因此由用户在新增或编辑台账时地图选点；已有台账保持原样，并列入“待定位”。点位是目标地址的位置，修改目标地址时提示复核坐标。页面不得将区中心或推测位置称为设备位置。

## 方案

- 数据库新增可空 `latitude DECIMAL(10,7)`、`longitude DECIMAL(10,7)`，两者同空或同有值；不改旧迁移、不回填旧记录。校验纬度 −90 至 90、经度 −180 至 180，接口以十进制字符串传递，保持精度。
- 沿用现有台账 POST、PUT、GET 和审计接口，新增字段进入完整记录与审计快照。新增只读 `GET /api/v1/ledgers/map-points`，返回 `{records:[{id,ledgerCode,destinationAddress,deviceCondition,latitude,longitude}],unlocatedCount}`，仅含未删除台账，records 为已定位记录，unlocatedCount 为未定位数量。
- 表单可在地图点选或手输坐标，保存时成对提交；首页每台记录一个标记，点击后打开现有完整详情。标记重叠时可借助列表选中目标记录。旧台账和未设坐标记录可从主表进入详情并补录。
- Excel 新模板末尾追加“纬度”“经度”，旧模板仍能导入且坐标为空；新模板导入时校验成对、范围与数值格式，导出应完整往返。
- 使用 Leaflet 和 OpenStreetMap 瓦片显示厦门底图，保留 OpenStreetMap 署名，只加载当前视口，断网时显示提示并保持台账列表可用。瓦片服务须遵守其使用政策，部署可配置其他合规服务。

## 实施与验收

Backend 负责迁移、DTO、校验、地图轻量接口、Excel 兼容及测试；Frontend 负责类型、选点表单、主页地图、详情与交互测试。每条已定位且未删除的台账恰有一个可访问的点位入口，点击能查看完整详情；旧记录、非法坐标、删除后的点位及 Excel 新旧模板均须验证。问题一、二已各自独立提交；本项测试通过后单独提交，最后运行前后端全套测试。
