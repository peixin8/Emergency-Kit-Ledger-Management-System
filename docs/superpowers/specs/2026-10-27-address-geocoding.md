# 目标地址搜索定位

用户在台账表单输入目标地址后，可主动点击“搜索地址”，从高德地图 Web 服务返回的候选地点中选择一个。选择只更新当前表单的 WGS84 经纬度并在地图上标示；目标地址文字保留原输入，保存台账时才持久化。候选点是地址解析的估计位置，用户须在地图上核对或微调。地图点选与手动输入经纬度继续可用。选择高德是因为当前电脑访问 OpenStreetMap Nominatim 的查询服务超时，而高德接口可连通。

## 接口

`GET /api/v1/geocoding/search?q=<地址>`，无需登录。地址去除首尾空白后长度为 2–255 字符。成功响应使用现有 `ApiResponse` 包装：`data.results` 最多 5 条，每条包含 `displayName`、`latitude`、`longitude` 字符串；坐标为 WGS84，最多七位小数。无匹配时返回空数组。非法地址返回 `400 VALIDATION_ERROR`；未配置高德 Key 返回 `503 GEOCODE_NOT_CONFIGURED`，Key 无效返回 `503 GEOCODE_INVALID_KEY`，账号封禁或配额耗尽返回 `503 GEOCODE_ACCOUNT_ISSUE`，频率限制返回 `429 GEOCODE_BUSY`，上游不可用返回 `503 GEOCODE_UNAVAILABLE`。错误和日志不得包含查询地址或 Key。

后端仅在收到搜索请求时调用高德 Web 服务地理编码 API，`city=厦门`、`output=json`，Key 从 `AMAP_WEB_SERVICE_KEY` 环境变量读取，不能写入源码、日志或前端。服务地址可配置供测试使用。高德返回 GCJ-02 坐标，后端须转换成现有 OpenStreetMap 地图和数据库所用的 WGS84；转换和地理编码本身都有误差，所以用户仍需在地图核对、微调。使用超时、有界 TTL 缓存及单实例默认每秒最多一次上游请求，降低共享用户耗尽 Key 配额的风险；多实例部署需要共享限流。前端不得在输入过程中自动发送查询。

## 验收

- 输入目标地址不会发起地理编码；点击搜索才发送当前地址。
- 候选可选择，选择后地图平移到该点，坐标字段更新；目标地址文字不被覆盖，台账仍需手动保存。
- 修改目标地址、切换台账或关闭表单后，旧候选和迟到的响应不会污染当前坐标。
- 空结果、限流和服务失败有清楚的中文反馈。
- 现有地图点选和坐标手填继续有效。
- 前后端相关测试、完整测试、类型检查、Lint 和构建通过后单独提交本功能。
